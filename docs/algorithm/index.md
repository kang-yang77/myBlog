# 算法知识体系梳理：

##  一、哈希表与数组

### 1. 补数 
* **适用场景**：寻找数组中满足 $A + B = Target$ 的元素组合。
* **核心逻辑**：
    * 摒弃 $O(N^2)$ 的暴力枚举。
    * 遍历时，询问：“**我的另一半（Target - Current）之前出现过吗？**”
    * **数据结构**：<code v-pre>HashMap<Value, Index></code>。
* **典型题目映射**：两数之和。

### 2. 归一化映射模式
* **适用场景**：将“外形不同但本质相同”的一类事物归类（如字母异位词）。
* **核心逻辑**：
    * 寻找一个**唯一的 Key** 来代表这一类数据。
    * **方法 A (排序)**：`"tea", "eat"` -> Key: `"aet"` (简单但 $O(K \log K)$)。
    * **方法 B (计数)**：统计字符频次 -> Key: `"1#0#2#..."` (高效 $O(K)$)。
* **典型题目映射**：字母异位词分组。

### 3. 检测与剪枝 
* **适用场景**：在无序数组中寻找连续序列。
* **核心逻辑**：
    * 利用 `HashSet` 去重并支持 $O(1)$ 查询。
    * **关键剪枝 (Smart Start)**：只有当 `num - 1` **不存在**于集合中时，才认定当前 `num` 是一个序列的**起点**，从而开始向后计数。
    * 这保证了每个数字只会被访问常数次，达成 $O(N)$。
* **典型题目映射**：最长连续序列。

### 4. 前后缀分解 
* **适用场景**：需要计算数组中某元素“左边所有”和“右边所有”的聚合结果（乘积、和、最大值等），且不允许除法或暴力嵌套。
* **核心逻辑**：
    * **预处理**：先从左往右扫一遍，计算 `Left[i]`。
    * **动态计算**：再从右往左扫一遍，用变量维护 `Right` 状态，实时计算结果。
    * **空间优化**：通常可以直接用结果数组 `Answer[]` 来存储前缀数据，从而省去额外空间。
* **典型题目映射**：除自身以外数组的乘积、接雨水（双指针优化的前身）。

### 5. 原地哈希与标记 
* **适用场景**：矩阵置零、原地寻找缺失的正数。
* **核心逻辑**：
    * 题目限制空间 $O(1)$，因此不能开新的数组或 Map。
    * **借用空间**：利用矩阵的**第一行**和**第一列**作为“标志位”数组。
    * **注意事项**：在使用第一行/列做标志位前，先记录第一行/列本身的状态（是否包含0），防止状态被覆盖后丢失。
* **典型题目映射**：矩阵置零。

### 6. 模拟与边界控制 
* **适用场景**：螺旋矩阵、旋转图像。
* **核心逻辑**：
    * 这类题没有复杂的算法，难点在于**下标控制**。
    * **分层模拟**：定义 `Top, Bottom, Left, Right` 四个边界。
    * **方向轮转**：按照 右 -> 下 -> 左 -> 上 的顺序循环，每填充完一条边，对应边界向内收缩 (`Top++`, `Right--` 等)。
* **典型题目映射**：螺旋矩阵。

## 二、双指针与滑动窗口

**核心哲学**：通过利用单调性或特定规则，将嵌套循环的 $O(N^2)$ 暴力解法优化为 $O(N)$ 的线性扫描。

### 1. 双指针 (Collision Pointers)
* **适用场景**：**有序数组**查找、容器盛水问题。
* **核心逻辑**：
    * 初始化 `left = 0`, `right = n - 1`。
    * 根据计算结果（如 `sum > target` 或 `height[left] < height[right]`）决定移动哪一边的指针。
    * **关键点**：利用贪心思想丢弃无效解空间。
* **典型题目**：
    * *盛最多水的容器*：谁短谁移动（因为移动长板只可能导致面积变小或不变）。
    * *三数之和*：排序后固定一个数，剩余两个数用双指针扫描（注意去重）。

### 2. 滑动窗口 (Sliding Window)
* **适用场景**：寻找满足条件的**子串**或**子数组**（最长/最短/定长）。
* **通用模板 (双循环/快慢指针)**：
    * **进窗 (`right` 主动)**：`right` 指针向右扩展，加入数据，更新窗口状态（如计数器、哈希表）。
    * **出窗 (`left` 被动)**：当窗口状态**不再满足条件**（或满足特定收缩条件）时，`left` 指针向右收缩，移除数据。
    * **更新结果**：在进窗或出窗的过程中更新 Max/Min 结果。
* **典型题目**：
    * *无重复字符的最长子串*：遇到重复字符，`left` 收缩直到重复字符被排除。
    * *找到字符串中所有字母异位词*：固定窗口大小，维护字符计数器。

### 3. 快慢指针 (Fast & Slow Pointers)
* **适用场景**：链表判圈、寻找中点、原地数组去重。
* **核心逻辑**：
    * `Fast` 每次走两步（或遍历原数组），`Slow` 每次走一步（或记录新数组位置）。
* **典型题目**：
    * *移动零*：`Fast` 找非零，`Slow` 记录放置位置。
    * *环形链表*：追及问题。

## 三、链表 (Linked List)

**核心哲学**：指针操作的艺术。难点不在算法，而在**鲁棒性**（空指针、断链、内存泄漏）。

### 1. 虚拟头结点 (Dummy Node)
* **痛点解决**：处理头结点可能被删除、改变的情况。
* **应用模式**：
    * `ListNode dummy = new ListNode(-1);`
    * `dummy.next = head;`
    * 最终返回 `dummy.next`。
* **典型题目**：*合并两个有序链表*、*删除链表的倒数第 N 个结点*。

### 2. 链表反转技巧 (Reversal Techniques)
* **迭代法 (三指针)**：`prev`, `curr`, `next`。每次只改一个箭头，稳步推进。
* **递归法**：利用递归栈触底反弹，从后往前修改指针。
* **K个一组翻转**：
    * 这是面试中的 **Hard** 题，考察代码掌控力。
    * 技巧：先判断剩余长度是否够 K 个，够则翻转，不够则保持。需维护“上一组结尾”和“下一组开头”。

### 3. 链表中的双指针
* **Floyd 判圈算法**：判断链表是否有环。
    * 如果有环，快慢指针必相遇。
    * **找环入口**：相遇后，一个指针重置到头，两指针同速走，再次相遇点即入口（数学证明需掌握）。
* **寻找中点/倒数第 N 个**：
    * 快指针先走 N 步，然后一起走。

## 四、二叉树与图 (Binary Tree & Graph)

**核心哲学**：遍历。一切树和图的问题，本质上都是 DFS 或 BFS 的变体。

### 1. 递归的思维跃迁 (The Leap of Faith)
* **核心心法**：写递归时，**不要**人脑模拟层层压栈。要假设子问题已经解决，只关注**当前节点**该做什么。
* **DFS 三部曲**：
    1.  **Base Case**：什么时候返回（空节点？叶子节点？）。
    2.  **递归拆解**：`root.left` 和 `root.right` 需要做什么？
    3.  **当前逻辑**：如何利用左右子树的返回值构建当前层的返回值？
* **典型题目**：
    * *二叉树的最大深度*：`max(左深, 右深) + 1`。
    * *翻转二叉树*：交换左右子树指针。
    * *二叉树的直径*：在后序遍历中，通过全局变量记录 `左深 + 右深` 的最大值。

### 2. BFS 层序遍历
* **数据结构**：`Queue` (Java 中通常用 `LinkedList`)。
* **分层技巧**：
    * 在 `while(!queue.isEmpty())` 内部，先获取当前 `size = queue.size()`。
    * 紧接着用一个 `for` 循环处理这 `size` 个节点。这能保证**同一层的节点被归在同一批处理**。
* **典型题目**：*二叉树的层序遍历*、*腐烂的橘子* (多源 BFS)。

### 3. 图的遍历 (Grid DFS/BFS)
* **适用场景**：网格图（岛屿问题）。
* **核心逻辑**：
    * **方向数组**：<code v-pre>int[][] dirs = {{0,1}, {0,-1}, {1,0}, {-1,0}}</code>。
    * **沉岛思想**：访问过的陆地 `1` 直接修改为 `0` 或 `2`，避免使用额外的 `visited` 数组，节省空间。
* **典型题目**：*岛屿数量*。

## 五、回溯与动态规划

**核心哲学**：解决**多阶段决策**问题。回溯是暴力穷举，DP 是带记事本的聪明穷举。

### 1. 回溯法 (Backtracking) - 决策树的遍历
* **通用模板**：
    ```java
    void backtrack(路径, 选择列表) {
        if (满足结束条件) {
            result.add(路径);
            return;
        }
        for (选择 : 选择列表) {
            if (不合法/已剪枝) continue;
            做选择;
            backtrack(路径, 选择列表);
            撤销选择; // 回溯的核心：恢复现场
        }
    }
    ```
* **排列 vs 组合 vs 子集**：
    * **全排列**：需要 `used` 数组记录谁用过。
    * **组合/子集**：引入 `start_index` 参数，防止往回选（去重）。
* **典型题目**：*全排列*、*子集*、*括号生成*。

### 2. 动态规划 (Dynamic Programming) - 状态转移
* **解题四步走**：
    1.  **定义状态 (`dp` 数组含义)**：最难的一步。`dp[i]` 是代表以 i 结尾？还是前 i 个？
    2.  **状态转移方程**：数学归纳法。`dp[i]` 如何由 `dp[i-1]` 或 `dp[i-2]` 推导？
    3.  **初始化 (Base Case)**：`dp[0]` 是什么？
    4.  **遍历顺序**：从前往后还是从后往前？
* **常见模型**：
    * **一维 DP**：*爬楼梯* (斐波那契)、*打家劫舍* (选或不选)。
    * **子序列/子串 (Subsequence)**：
        * *最长递增子序列 (LIS)*：$O(N^2)$ 经典 DP，`dp[i]` 表示以 `nums[i]` **结尾**的最长长度。
    * **背包问题变体**：
        * *零钱兑换*：完全背包（物品无限用），求最少硬币数。
    * **二维 DP**：
        * *最长公共子序列 (LCS)*：处理两个字符串的问题。

### 3. 贪心与 DP 的区别
* **贪心**：每一步都选局部最优，且局部最优能导致全局最优（如 *跳跃游戏*）。
* **DP**：记录所有可能的状态，通过比较得出全局最优。如果面试时贪心证不出来，老老实实写 DP 或回溯。
