# LIS 算法总结

## 一、 两种类型


### 1. 动态规划 (DP)
* **复杂度**：$O(N^2)$
* **适用场景**：$N \le 5000$，或者**题目求的不是“长度”而是“权重和”**（如“无矛盾最佳球队”）。
* **口诀**：`dp[i]` 表示以 `i` 结尾的最优解。回头看所有的 `j < i`，只要能接上 (`nums[j] < nums[i]`)，就尝试转移。
* **核心代码**：
    ```java
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < i; j++) {
            // check(j, i) 是能不能接上的条件
            if (check(j, i)) {
                dp[i] = Math.max(dp[i], dp[j] + val[i]);
            }
        }
    }
    ```

### 2. 剑宗：贪心 + 二分 (Greedy + Binary Search)
* **复杂度**：$O(N \log N)$
* **适用场景**：$N \ge 10^5$，**只求最长子序列的长度**。
* **口诀**：维护一个 `tails` 数组（或 `f` 数组）。`tails[k]` 存的是**长度为 `k+1` 的子序列中，结尾最小的那个数**（潜力最大）。
* **操作逻辑**：
    * 如果你比 `tails` 最大的还大 $\rightarrow$ **直接追加**。
    * 如果你夹在中间 $\rightarrow$ **二分查找**，把那个“占着茅坑不拉屎”（数值大但长度短）的数替换掉，让序列更紧凑。

## 二、 🗺️ LIS 变种题型地图

我们在做题时，LIS 从来不会直接出现，它总是披着各种马甲。以下是破解马甲的通用公式：

| 题目类型 | 典型特征 | 破解关键 (Key Trick) | 代表题目 |
| :--- | :--- | :--- | :--- |
| **基础版** | 求最长上升子序列长度 | 直接上 $O(N \log N)$ 模板。 | LeetCode 300 |
| **非严格递增** | `nums[i] >= nums[j]` (可以相等) | 二分查找换成 **Upper Bound** (找第一个**严格大于**你的位置替换)。 | LeetCode 1964 (障碍赛跑) |
| **二维 LIS** | 信封嵌套、身高体重排序 | **排序杀招**：第一维度**升序**，第一维度相同时，第二维度**降序**。然后对第二维度求 LIS。 | LeetCode 354 (俄罗斯套娃) |
| **最少删除/修改** | 问最少删几个变成上升 | **逆向思维**：最少删除 = 总长度 - **最长能保留的(LIS)**。 | LeetCode 2111 (K递增) |
| **双向 LIS** | 山脉数组 (先升后降) | **前后缀分解**：正着求一遍 `pre[]`，倒着求一遍 `suf[]`，枚举山顶 `i`，答案是 `pre[i] + suf[i] - 1`。 | LeetCode 1671 (山形数组) |
| **带权 LIS** | 求最大分数/总和 (不是长度) | **必须回归 DP**。不能用贪心二分（因为小的数分值不一定高）。如果非要 $O(N \log N)$，需配合**树状数组/线段树**优化 DP。 | LeetCode 1626 (最佳球队) |
| **分组 LIS** | 隔 K 个数递增 | **取模分组**：把数组按 `i % k` 分成 `k` 组，每组单独求 LIS，最后累加。 | LeetCode 2111 (K递增) |

## 三、 ⚠️ 易错点排雷 (Debug 手册)

### 1. 二分写的对不对？
* **严格递增 (1, 2, 3)**：找第一个 `>=` 当前数的位置 (`lower_bound`)。
    * *意图*：如果找到相等的，替换它（不增加长度）。
* **非严格递增 (1, 2, 2, 3)**：找第一个 `>` 当前数的位置 (`upper_bound`)。
    * *意图*：如果找到相等的，`l` 会跳过去，最终插入到相等的数**后面**（增加长度）。

### 2. 二维排序为什么降序？
* 如果 `[6, 7], [6, 8]` 按 `w` 升序且 `h` 升序排，`h` 数组变成 `..., 7, 8, ...`。
* LIS 算法会以为 `7` 和 `8` 可以连起来，长度 +2。
* 但实际上 `w` 都是 6，`[6, 7]` 装不进 `[6, 8]`。
* **Trick**：让 `h` 降序变成 `[6, 8], [6, 7]` $\rightarrow$ `h` 数组为 `..., 8, 7, ...`，LIS 只能选一个，完美避坑。

### 3. 求和别贪心！
* 一旦题目变成了求数值的 **Sum**（如最佳球队），**千万别用 `tails` 贪心数组**。
* `tails` 数组里的顺序和原数组的真实路径是不一样的，它只是一个“长度记录器”，丢失了“和”的信息。必须老老实实写 `dp[i]` 或用线段树。

## 四、 💎 下一步修炼建议

既然 LIS 已经拿捏了，作为 ACM 大神之路的下一站，建议你挑战这两个方向，它们和 LIS 都有千丝万缕的联系：

1.  **最长公共子序列 (LCS) 及其转化**
    * *你知道吗？* 如果两个数组中有一个是**元素不重复**的，LCS 问题其实可以转化为 LIS 问题，从而把复杂度从 $O(N^2)$ 降到 $O(N \log N)$！这在处理排列 (Permutation) 类题目时是必杀技。

2.  **区间 DP (Interval DP)**
    * LIS 是线性 DP 的代表。下一步可以试试区间 DP，比如“石子合并”、“回文子串”等。这里的思维方式是从“从左向右扫”变成“从小区间合并成大区间”。
